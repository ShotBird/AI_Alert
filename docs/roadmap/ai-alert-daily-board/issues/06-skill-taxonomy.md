# 06. GitHub 스킬 부문 택소노미 확정

Type: grilling
Status: resolved
Blocked by: (없음)

## Question

"디자인·백엔드·프론트엔드·계획 등 부문별 랭킹"을 원하셨는데, **GitHub에는 그런 분류 필드가 없다.**
`topic:claude-skills` 태그에 8,726개 레포가 있지만 태그는 자유 문자열이고 일관성이 없다.
따라서 부문은 **우리가 정의하고 LLM이 설명문을 읽어 분류**해야 한다.

정해야 할 것:

- 부문 목록을 확정한다. 초안: 디자인 / 프론트엔드 / 백엔드 / 계획·기획 / 데이터·분석 / 문서·글쓰기 / 기타
  — 너무 잘게 쪼개면 부문마다 한두 개씩만 남아 랭킹이 무의미해진다
- **"핫하다"의 기준**: 누적 스타 수인가, 최근 7일 스타 증가분인가, 신규 생성인가?
  누적으로 하면 같은 레포가 몇 달 내내 1등이라 매일 볼 이유가 없어진다
- 분류가 애매한 레포(여러 부문에 걸침)를 어떻게 처리하는가
- 분류 결과를 캐시하는가 — 같은 레포를 매일 다시 분류하면 돈과 시간이 낭비된다

`grilling` + `domain-modeling` 스킬을 호출할 것.

---

## Answer

> **에이전트가 대신 결정함** (2026-09-20 야간 자율 세션).
> **이 티켓은 사용자가 제안한 부문 구분이 데이터와 맞지 않는다는 결론이다.** 아침에 꼭 확인할 것.

### 실측: 상위 199개 레포를 직접 읽었다

`topic:claude-skills`와 `topic:agent-skills`에서 상위 199개를 받아 설명을 하나씩 읽고 분류했다.

**62%가 랭킹에 쓸 수 없는 것이었다.**

| 종류 | 비율 | 예 |
|---|---|---|
| **모음집** (awesome-list, "스킬 380개 묶음") | **35%** | `VoltAgent/awesome-openclaw-skills`, `ComposioHQ/awesome-claude-skills` |
| **무관 제품** (토픽 태그만 달아둔 앱·프레임워크) | **20%** | `kubesphere/kubesphere`, `reactive-resume`, `tinybase` |
| **분류 불가** (설명이 없거나 뜻을 알 수 없음) | **7%** | 설명 없음, "Helping the Agents Compose the Things" |

모음집은 레포 하나가 스킬 수백 개라서, **"오늘 뜨는 스킬"에 섞으면 랭킹이 무너진다.**

### 제안하신 부문은 절반만 맞았다

| 제안 부문 | 실제 | 판정 |
|---|---|---|
| **디자인** | 약 17개 (다이어그램·UI·프레젠테이션) | ✅ 충분하다 |
| **계획** | 약 6개, 오케스트레이션 도구와 섞임 | ⚠️ 얇다 |
| **백엔드** | 약 8~9개, .NET·Go·Terraform·Postgres·AWS로 **제각각** | ⚠️ 하나의 부문으로 안 읽힌다 |
| **프론트엔드** | **약 4개** | ❌ 부문으로 성립 안 함 |

대신 **제안에 없던 부문이 더 크다**: 글쓰기·콘텐츠 11, 메모리·컨텍스트 10, 마케팅·SEO 10, 비즈니스·금융 10, 연구·과학 8.

### 그래서 부문별 랭킹을 포기한다

잡음 62%를 걷어내면 단일 목적 스킬이 76개 남는다.
**부문 5개 × 상위 5개 = 25칸을 채우려면 부문마다 실제 후보가 8개는 있어야 하는데, 그런 부문이 5~6개뿐이다.**
"6개 중 상위 5개"는 랭킹이 아니다.

**대신 이렇게 한다** — [05](05-daily-board-schema.md)의 "섹션당 5개" 계약과도 맞아떨어진다:

> GitHub 섹션 = **7일 스타 증가분 상위 5개**, 각 카드에 **부문 라벨**을 배지로 단다.

부문이 **랭킹의 축이 아니라 라벨**이 된다. 상위 5개는 자연히 여러 부문에 흩어지므로
"오늘은 디자인 둘, 메모리 하나, 마케팅 둘"처럼 다양성은 그대로 보인다.
칸을 억지로 채우지 않아도 되고, 부문이 얇아도 무너지지 않는다.

### 부문 라벨 (데이터가 지지하는 것)

디자인·비주얼 / 글쓰기·콘텐츠 / 메모리·컨텍스트 / 마케팅·SEO / 비즈니스·금융 /
인프라·백엔드 / 연구·과학 / 보안 / 브라우저 자동화 / 스킬 제작 / 계획·오케스트레이션 / 기타

### 제외 규칙 (랭킹 진입 전에 적용)

1. **모음집 제외** — LLM 분류가 `is_collection`을 함께 판정한다
2. **무관 제품 제외** — 토픽만 달았을 뿐 에이전트 스킬이 아닌 것
3. **설명 없음 제외** — 요약도 분류도 불가능하다

모음집은 버리기 아깝다면 나중에 "모음집" 한 줄을 따로 두면 된다. 랭킹에는 섞지 않는다.

### 분류는 LLM 1회 패스, 캐시는 한다

`설명 + 토픽`을 넣어 부문과 `is_collection`을 받는다. 레포당 입력 60토큰·출력 10토큰 수준이다.

| | 하루 100개 | 하루 300개 |
|---|---|---|
| Haiku 4.5 | $0.011 | $0.033 |
| Sonnet 5 | $0.022 | $0.066 |

**비용 때문에 캐시하는 게 아니다 — 일관성 때문에 한다.** 같은 레포가 어제는 "디자인", 오늘은 "기타"로 찍히면
[05](05-daily-board-schema.md)의 `change: continuing` 판정이 흔들린다. 레포별 분류 결과를 저장해두고 재사용한다.

**토픽 태그만으로는 분류가 안 된다.** 실측 결과 태그가 `claude-code`·`mcp`·`cursor` 같은
**도구 이름에 지배**당해서, 도메인 신호는 소수에만 붙어 있다. LLM 패스가 필요하다.
