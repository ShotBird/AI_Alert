## Question

사용자 보고: "보드를 불러오는 중입니다.. 만 뜨고 아무것도 안나옴.
원인 파악하고 니가 왜 못걸렀는지 분석해서 재발방지해"

## Answer

### 원인 1 — 렌더 함수가 지워진 채 배포됨

커밋 `b9b97c2` 가 `web/index.html` 의 렌더 함수 **10개를 통째로 지웠는데
호출부는 남겼다.** `renderBoard` 가 첫 줄 `renderKeywordStrip(...)` 에서
`ReferenceError` 로 죽으니 그 뒤가 전부 안 그려지고 로딩 문구만 남았다.

복구한 것: `renderKeywordStrip` `keywordPillHTML` `toggleKwDetail`
`keywordCardHTML` `isVendorCard` `fmtWhen` `vendorTableHTML`.
(`bindGithubEvents` `reactionBar` 는 의도적 교체였으므로 복구하지 않았다.)

`plainCardHTML` 은 **이전 버전에도 없었다** — 낯선 섹션 하나가 페이지 전체를
죽일 수 있는 구멍이 오래 열려 있었다. `cardHTML` 과 함께 낙하 지점으로 신설했다.

### 원인 2 — 서비스 워커가 깨진 화면을 캐시에 가둠

셸이 **'캐시 우선 + 고정 캐시 이름'** 이었다. 깨진 `index.html` 이 기기 캐시에
박힌 뒤로는 고쳐서 배포해도 화면이 그대로다. 캐시 이름을 손으로 올리는 규칙에
기대고 있었고, 잊었다. (로컬 점검 중 `ai-alert-shell-v1` 이 실제로 옛 셸을
내주고 있는 것을 확인했다.)

→ 셸을 **stale-while-revalidate** 로 바꿨다. 캐시본을 즉시 내주되 매번 뒤에서
새로 받아 덮고, 내용이 달라졌으면 열린 창에 알린다. 페이지는 **세션당 한 번만**
새로고침한다(잠그지 않으면 갱신 실패 시 무한 새로고침). 캐시 이름 v1 → v2.

### 왜 못 걸렀나

파이프라인 JSON 과 파이썬 테스트 51개만 보고 통과라고 했다.
**"JSON 이 옳다"와 "화면이 그려진다"는 다른 명제인데** 그 사이를 아무도 보고
있지 않았다. `daily.yml` 에는 테스트 단계가 **하나도 없었다.**
고친 뒤 재배포도 빠뜨려서, 사용자가 다시 지적하고 나서야 알았다.

### 재발방지

- **`tests/test_render.py` 14개** — 정의 없이 호출되는 함수, `el` 이 가리키는 id 가
  문서에 있는지, 보드의 모든 섹션에 렌더 분기가 있는지, `sw.js` 가 셸을 캐시에
  가두지 않는지. 브라우저를 쓰지 않는다(이 앱은 pip 없이 도는 게 원칙).
  **렌더 함수를 일부러 지워 실제로 FAIL 나는 것까지 확인했다** — 통과만으로는 증거가 아니다.
- **CI 에 테스트 단계 신설.** 보드 생성 전에 65개를 돌리고, 생성 후 오늘 보드로
  렌더 계약을 한 번 더 본다. 막히면 배포까지 가지 않는다.
