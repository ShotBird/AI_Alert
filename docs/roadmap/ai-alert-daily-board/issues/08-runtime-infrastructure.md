# 08. 실행 인프라 확정

Type: grilling
Status: open
Blocked by: (없음)

## Question

매일 한 번 수집·요약을 돌리고 결과 JSON을 폰이 읽을 수 있는 곳에 올리는 구조를 확정한다.

후보:

- **GitHub Actions + GitHub Pages**: 공개 레포면 완전 무료. 다만 예약 실행이 **수 분~수 시간 지연**되고,
  공개 레포는 60일간 활동이 없으면 예약이 자동 비활성화된다
- **Cloudflare Workers + Cron Triggers**: 무료 티어로 충분하고 정시 실행이 훨씬 정확하다.
  대신 실행 시간 제한이 있어 무거운 처리가 어려울 수 있다
- **혼합**: Cloudflare가 정시에 깨워서 GitHub Actions를 `workflow_dispatch`로 호출 (조사 권고안)

함께 정할 것:

- **레포를 공개로 할 것인가** — 무료 CI와 Pages를 쓰려면 공개가 유리하지만,
  개인 관심사와 수집 소스 목록이 드러난다. API 키는 어차피 커밋하지 않지만 판단이 필요하다
- 사용자가 정한 시각을 어떻게 반영하는가 — cron을 매번 바꿀 수는 없으니,
  **자주 생성해두고 알림만 지정 시각에** 보낼 것인가?  이게 이 티켓의 핵심 설계 질문이다
- 오늘 것이 제시간에 안 나왔을 때 사람이 어떻게 아는가
- **무료 강제 장치를 어디에 둘 것인가** -- 일일 호출 카운터의 저장 위치(리포 커밋? 실행 환경 로컬?), fail-closed 처리, 개발 중 실수로 실제 API를 때리지 않게 하는 방법(fixture + --live 플래그), 매일 메일에 "네이버 12/300" 같은 사용량 한 줄 넣기

`grilling` + `domain-modeling` 스킬을 호출할 것.
