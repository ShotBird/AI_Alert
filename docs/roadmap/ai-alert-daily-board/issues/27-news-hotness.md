# 27. 뉴스 Top5 가 '가장 핫한 뉴스'가 맞는가

Status: → GitHub Issue #27 (상태·라벨은 거기가 정본이다)
Blocked by: (없음)

## Question

사용자 지적: "지금 뉴스탭은 메인 헤드라인이 아닌 것 같다. 가장 Hot한 AI 뉴스를
국내/해외에서 뽑아오고 싶은데, 그게 맞는지 점검하고 아니면 수정해."

화제도([05](05-daily-board-schema.md))는 이렇게 생겼다:

```
heat = (3·log2(1+출처수) + log10(1+반응+2·댓글) + 출시보너스) × 0.5^(경과/20h)
```

출처 수가 가장 큰 항이다. **여러 매체가 같은 사건을 동시에 받아쓰면 그게 화제다**
라는 판단이 이 식에 들어 있다. 그런데 그 항이 실제로 작동하고 있는지 잰 적이 없다.

## Answer

**지적이 맞았다. 측정해 보니 100개 묶음 전부 `source_count == 1` 이었다.**
출처 항이 항상 `3·log2(2) = 3.0` 으로 고정되니 화제도는 사실상 `3.0 × 최신도`,
즉 **순수 최신순**이었다. 매체 교차 검증이 한 건도 일어나지 않고 있었다.

원인 세 가지:

1. **Hacker News 가 아예 섹션에 못 들어왔다.** `sources.py` 가
   `hn.algolia.com/api/v1/search` 를 쓰고 있었는데 이건 **관련도순·전체기간**이다.
   60건을 받아도 4일 창 안에 드는 것이 1건뿐이었다.
   → `/search_by_date`(최신순)로 바꾸고 `hitsPerPage` 60 → 500.
2. **`TOKEN_THRESHOLD` 0.60 이 너무 빡빡했다.** 실제 중복 기사 쌍의 자카드 유사도를
   재보니 0.13 까지 내려갔다 (매체마다 제목 어휘가 다르다).
   → 0.12 로 낮추고, 대신 `MIN_SHARED=3` 이 실질적 판별을 맡게 했다.
   `ai/was/were/been/went/rogue` 를 `STOPWORDS` 에 추가.
3. **묶음 정체성이 '처음 들어온 항목'에 묶여 있었다.** 새 항목을 창시자 제목하고만
   비교하니, 같은 사건이라도 창시자와 표현이 다르면 새 묶음이 됐다.
   → 후보 묶음 **안의 모든 항목**과 비교하도록 변경.

### 결과 (실측)

| | 이전 | 이후 |
|---|---|---|
| 매체 교차 묶음 | 0 / 100 | 10 / 135 |
| 해외 최고 화제도 | 2.43 | 5.00 |

4개 매체가 함께 받아쓴 기사(TechCrunch + The Verge + Techmeme + HN)와
2개 매체가 받아쓴 국내 기사가 실제로 잡혔다.

`rank.py` 의 가중치는 **일부러 건드리지 않았다.** 식이 틀린 게 아니라
식에 들어갈 입력이 없었던 것이므로, 입력을 고치는 게 맞다.
