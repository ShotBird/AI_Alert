# 10. GitHub "급상승" 신호를 어떻게 만들 것인가

Type: grilling
Status: open
Blocked by: (없음)

## Question

[01](01-verify-source-feeds.md)에서 확인된 것: **GitHub API에 "최근 스타 증가분" 필드가 없다.**
응답에는 누적 `stargazers_count`와 `pushed_at`뿐이다.
누적으로 랭킹하면 같은 레포가 몇 달 내내 1등이라 **매일 열어볼 이유가 사라진다.**

선택지:

1. **우리가 매일 스냅샷을 떠서 차분한다** — 하루 한 번 상위 N개 레포의 스타 수를 저장하고 어제와 비교.
   정확하지만 며칠 쌓여야 의미가 생긴다(첫날은 빈 섹션). 저장 위치와 추적할 레포 수를 정해야 한다
2. **`created:>날짜`로 신규 레포만 본다** — 증가분 대신 "이번 주에 새로 생긴 것 중 스타 많은 것".
   첫날부터 동작하고 구현이 단순하다. 단 오래된 강자가 갑자기 뜨는 경우를 놓친다
3. **비공식 트렌딩 스크래퍼 API에 의존** — GitHub 트렌딩 페이지를 긁어 API로 파는 서비스들.
   GitHub이 마크업을 바꾸면 조용히 깨진다
4. **1 + 2 혼합** — 초반엔 2번으로 채우고, 스냅샷이 쌓이면 1번으로 전환

정할 것: 어느 방식인가, 몇 개 레포를 추적하는가, 스냅샷을 어디에 저장하는가(리포에 커밋? 별도 파일?),
그리고 [06](06-skill-taxonomy.md)의 부문 분류 결과를 어떻게 캐시할 것인가.

`grilling` + `domain-modeling` 스킬을 호출할 것.
