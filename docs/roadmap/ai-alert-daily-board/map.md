# 지도: AI Alert 데일리 보드

label: wayfinder:map
charted: 2026-09-20

## Destination

내 아이폰 홈화면에서, 매일 내가 정해둔 시각에 AI 동향 다섯 섹션이 한국어로 정리된 보드가 실제로 열리는 것.
스펙 문서가 아니라 동작하는 물건이 목적지다.

## Notes

- **실행까지 포함한다.** wayfinder 기본값(계획까지만)을 의식적으로 override. 티켓은 결정뿐 아니라 구현도 담는다.
- **사용자는 비개발자다.** 티켓은 "무엇을 왜"까지 한국어로 쓰고, HITL 티켓은 클릭 단위 체크리스트로 준다.
- 모든 세션은 `docs/agents/issue-tracker.md`(이슈 규약)와 `docs/agents/domain.md`(용어)를 먼저 읽는다.
- **화면을 건드리는 세션은 리포 루트 `DESIGN.md`를 먼저 읽는다.** 손으로 고치지 않는다.
- **용어는 `CONTEXT.md`를 따른다.** 보드·섹션·항목·묶음·카드·화제도·브리핑·키워드·변화·스테일. 동의어를 새로 만들지 않는다.
- 결정 티켓은 `grilling` + `domain-modeling` 스킬을 호출한다.
- **브랜치 규칙**: 계획 문서는 master 직접. 구현은 티켓당 `feat/<슬러그>`. 검증 에이전트는 같은 브랜치 위에서 돌고, 통과해야 master로 병합.
- **약관 준수가 설계 제약이다.** 차단을 회피하는 수집은 만들지 않는다. 막힌 소스는 우회하지 말고 기능을 재정의한다.
- **피드가 "존재한다고 보고됨"은 근거가 아니다.** 01에서 차단 페이지를 그럴듯한 RSS 요약으로 지어낸 사례가 실제로 나왔다. 쓰기 전에 직접 호출해 확인한다.
- **무료 구간을 넘지 않는 책임은 우리 코드에 있다.** NCP에 결제수단이 등록돼 있고 종량제다. 콘솔 알림은 하드 차단이 아니다. 모든 외부 API 호출은 일일 카운터를 통과해야 하고, 카운터를 읽지 못하면 호출하지 않는다(fail-closed). 상한은 무료 구간의 2% 이하로 잡는다 -- 네이버 검색 일 300회, 검색어 트렌드 일 20회.

## Decisions so far

- [01. 소스 피드 실동작 검증](issues/01-verify-source-feeds.md): 전 소스를 직접 호출해 확정.
  뉴스는 넉넉하지만 **Anthropic·xAI·Meta·DeepSeek는 RSS가 없고(→09), GitHub은 스타 증가분 필드가 없으며(→10), 클리앙은 피드 경로 자체가 없다.**
  전자신문 주소는 `rss.etnews.com/04046.xml`로 정정. VentureBeat·ZDNet Korea는 폐기.
- [04. 알림 채널 확정](issues/04-notification-channel.md): **아이폰 단축어 시간 자동화 + 이메일 백업.**
  서버·토큰·배포가 전부 사라지고, 사용자가 시각을 폰에서 직접 바꾼다. 카카오는 60일 토큰 절벽, 웹 푸시는 서버 없음 전제와 충돌해 탈락.
- [05. 일일 보드 스키마와 다섯 섹션의 내용 확정](issues/05-daily-board-schema.md): **섹션이 5개에서 4개로 줄었다.**
  커뮤니티는 독립 섹션이 아니라 키워드에 붙는 한국 반응이고, GeekNews는 뉴스 수집원으로 들어간다.
  섹션당 5개·원문 제목+한국어 요약·어제 대비 변화 배지·14일 보관. 계약은 `latest.json` 하나.
  용어는 `CONTEXT.md`에 고정했고 "핫도"는 **화제도**로 교체.

- [06. GitHub 스킬 부문 택소노미 확정](issues/06-skill-taxonomy.md): **제안한 부문이 데이터와 맞지 않았다.**
  상위 199개를 읽어보니 62%가 모음집·무관 제품·설명 없음이고, 프론트엔드는 레포가 4개뿐이다.
  부문별 랭킹을 버리고 **단일 랭킹 + 부문 배지**로 바꿨다.
- [07. PWA 화면 시안](issues/07-pwa-screen-prototype.md): 4개 섹션 세로 펼침, 브리핑이 첫 화면에 들어온다.
  다크 모드는 `DESIGN.md` 안의 토큰만으로 역할을 뒤집어 해결(Void 바탕 / Obsidian 카드). 새 색을 만들지 않았다.
  시안: https://claude.ai/artifact/HfdswiX5pGcTbkLd8cVTNF
- [08. 실행 인프라 확정](issues/08-runtime-infrastructure.md): **비공개 리포 + Cloudflare Pages.**
  GitHub Free는 비공개 리포에 Pages를 안 준다. 비용이 같다면 키가 새도 덜 아픈 쪽을 고른다.
  "사용자 지정 시각"은 질문 자체가 틀렸다 — 시각은 폰(단축어)이 알고 서버는 하루 한 번 돌 뿐이다.
- [09. RSS 없는 벤더](issues/09-vendor-news-without-rss.md): 네 벤더 모두 robots.txt가 크롤링을 허용한다(x.ai는 AI 이용을 명시 허용).
  Anthropic은 살아있는 미러 피드, Meta/DeepSeek은 HF 교차검증, **xAI만 공백**이나 차단이 아니라 간헐적 불안정 수준.
  부수 발견: **회사명으로 필터하면 소송·정치가 딸려오고 제품명으로 걸어야 발표가 잡힌다.**
- [10. GitHub 급상승 신호](issues/10-github-trending-signal.md): **전제가 틀렸다.** GitHub에 스타 히스토리 엔드포인트가 있다
  (`/repos/{o}/{r}/stargazers/history`, 직접 호출해 확인). 스냅샷 DB가 불필요해졌고 **첫날부터 진짜 주간 랭킹**이 나온다.
  대가로 GitHub 토큰이 필요해졌다(무인증 core는 시간당 60회).

## Not yet specified

- LLM 요약 프롬프트 설계와 한국어 품질을 어떻게 검증할 것인가 — API 키가 생긴 뒤
- 화제도 계수 튜닝 — 근거 세 가지는 고정됐고, 실제 데이터를 며칠 모아 가중치를 정해야 한다
- 묶음 판정 임계값 — 어디까지를 "같은 사건"으로 볼 것인가. 느슨하면 다른 소식이 합쳐지고, 빡빡하면 같은 소식이 5칸을 먹는다
- 검증 에이전트가 무엇을 검사해야 하는가 — 외부 피드에 의존해 테스트가 어려운 파이프라인에서
- velog에서 실제로 추적할 작성자 목록 — 메커니즘은 확인됐고 대상 선별이 남았다
- 모음집 레포를 따로 보여줄 것인가 — 랭킹에서는 뺐지만 가장 큰 무리라 버리기 아깝다

## Out of scope

- 네이티브 iOS 앱($99/년 + CI 서명 파이프라인) — 목적지 밖. 원하면 새 지도를 그린다
- 앱스토어 배포, 타인 공유, 로그인/회원가입
- Threads 트렌딩 피드 — 공식 API에 해당 기능 자체가 없음 (keyword_search는 별건, [03](issues/03-reddit-oauth-application.md) 참고)
- 디시인사이드 수집 — 이용약관이 비영리·개인 포함 자동 수집을 전면 금지
- 텔레그램을 수집원으로 사용 — 봇 약관이 공개 채널 집계를 명시적으로 금지 (알림 발신은 약관상 문제없으나 04에서 단축어에 밀려 탈락)
- 클리앙 수집 — 피드 경로가 존재하지 않고, HTML 스크래핑은 이 프로젝트의 수집 원칙 밖
